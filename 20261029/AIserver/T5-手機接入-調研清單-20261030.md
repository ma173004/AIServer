# T5 手機接入與操控：明天調研清單（2026-10-30）

目標：讓映月能穩定拿到手機上的資訊（e-class 時間表/通知、到校放學、定位），必要時能操控手機（讀取介面→操控→再讀取）。今天先不確定技術，只列「要查什麼、查到什麼程度算可以動工」。

## A. 手機基本資料（先查這些）
1. 型號、Android 版本、廠牌 UI（MIUI/ColorOS/…）— 決定能否裝第三方 app、背景限制多不多。
2. 是否能開啟「通知存取權限」（NotificationListener）給自寫/開源 app。
3. 是否願意長期插電＋連 WiFi（夜間跑任務）。
4. 有無 root；沒有 root 也可以，先確認。
5. 手機與伺服器（10.0.0.2）是否同一網段／能否互連（ADB over WiFi 或 HTTP 回報）。

## B. 方案路線（查可行與限制，先選一條主線）
1. **通知轉發 app**（Notify → HTTP POST 到伺服器）：查有沒有現成 app（如 Notification Forwarder）或要自寫小 app；權限與延遲。
2. **ADB + UI Automator / scrcpy**：伺服器端用 `adb` 驅動手機（需開發者選項＋USB/無線配對）。查：夜間穩定嗎？解鎖螢幕需不需要密碼？
3. **自動化 app**（Tasker / MacroDroid）：定時定位上報、拍卡後抓通知、按時開 e-class。查免費版夠不夠。
4. **截圖＋伺服器 VLM OCR**：手機定時截圖上傳 → 伺服器 Qwen3-VL 讀（已有 VLM 生命週期管理）。查哪種截圖方式最省電。
5. **e-class 網頁抓取**：如果 e-class 有網頁版，伺服器用 Playwright 登入抓時間表/考試表（比操控手機穩）。**最優先查這個**。
6. **定位**：Tasker/自動化定時取 Fused 定位 → HTTP 上報；或 Google 定位分享。查耗電與精度。

## C. e-class 具體要查
1. e-class 是網頁版還是只有 app？網址？
2. 時間表（上課/放學）、考試表、假期公告在哪個頁面？手機截圖一張給我看結構。
3. 網頁版能否用同一組帳密登入？有沒有 2FA/驗證碼？
4. 拍卡通知的實際文字（例：「已到校 08:02」）長什麼樣？會同時發 email/推送嗎？
5. 考試週的上下學時間變動怎麼公布（校曆/公告）？

## D. 操控的邊界與時機
1. 操作手機只安排在**晚上主人睡覺或不用手機時**（主人指定）。
2. 優先只做「讀取」（通知/截圖/網頁）；「操控」（點擊/輸入）等讀取穩定後再開。
3. 電量、發熱、鎖屏、勿擾模式要先確認不會吵到主人。
4. 手機解鎖密碼之類的敏感資訊放 `.secrets`，不寫進 prompt/日誌/git。
