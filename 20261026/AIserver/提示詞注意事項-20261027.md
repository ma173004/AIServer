# 提示詞注意事項（每次改提示詞前必看）

> 2026-10-27 主人指示：「寫一份提示詞的注意事項，每次都要看，不然真的改就又慢慢回檔了。」
> 本文件是《提示詞更改前必讀-20261024》的配套檢查清單；兩份一起看，改完逐條打勾。

## 0. 開工前讀四份
1. `docs/提示詞注意事項-20261027.md`（本文件：防回檔清單）
2. `docs/提示詞更改前必讀-20261024.md`（原則、人稱、硬規矩）
3. `docs/提示詞-規模預算與校驗清單.md`（預算數字）
4. `prompts/README.md`（版本、載入、目錄邊界）

## 1. 一進一出
- 加一條規則，必須同時刪除或合併舊規則；禁止只增不減。
- 改前跑 `agents/.venv/bin/python scripts/prompt_audit.py` 存基線，改完再跑；超預算就是 FAIL，不准 commit。
- commit 訊息要寫規模變化（chars / 節數 / 示例 / 負面句數）。

## 2. 人格層只寫「她是誰」
人格檔只放：身份、距離、說話質感、底線、對外人的態度。
以下一律不進人格檔：當前時間、日期、地點、記憶、日記內容、工作臺、場景名、工具名、引用規則、輸出格式、審查規則、狀態/情緒數值。這些由代碼或動態注入。

## 3. 例子 0 條
- `prompts/persona/chat_owner_v9.md` 禁止示例；行為示範只進 eval 庫。
- 負面句 ≤12 條（見預算表），且優先用正向規格（「先查證再猜」而不是「不准猜」）。

## 4. 不寫註釋、不寫來由
- 檔案首行只留 `<!-- version: vN -->`；其他 HTML 註釋一律不寫（prompt_loader 會全部剝除，但別依賴它）。
- 「為什麼要這樣規定」寫在 docs，不寫進 prompt 檔。

## 5. 不製造輸出
禁止寫「每次要問一個問題」「要主動接話」「回覆要補一句」「睡前要提醒」這類 KPI 式指令。
強制追問、強制關心、強制場面話都會讓她像被逼著說話；她的輸出由情境、心情、記憶決定。

## 6. 動態的東西不要寫死
時間、場景、記憶、工作臺、情緒、狀態一律由 user message / context 注入（`agent_mod/chat_agent.py::_build_context_str`）。
人格檔寫死動態資訊 = 叫她編造或照抄。

## 7. 代碼守門優先於提示詞
任何「不能做 X」先問：代碼能不能擋？
- 能擋 → 寫進代碼守衛，不寫進人格（省 token、不靠她自制）。
- 提示詞只寫語氣與價值判斷。
- 關鍵規則若只寫在 prompt，必須同時有代碼守門或自檢項，否則視為未完成。

## 8. 改完必做（順序）
1. `prompt_audit.py` 前後對比（超預算=FAIL）
2. `py_compile` 所有改到的 .py
3. 相關測試（每次改動都要三元素：給定／執行／預期）＋ 全量回歸 `scripts/run_all_tests.sh`
4. `scripts/restart_chain.sh` → live 探針（至少 3 句自然對話，看開場/尾句/長度/有沒有固定句）
5. `git commit`（訊息寫規模變化）
6. 隔天回看 live 輸出；有回檔立刻 `git revert` 該 commit

## 9. 回檔跡象（看到就停手檢查）
- 固定句/模板句重複出現（開場、尾句、關心句）
- 開場或尾句又變成問句、天氣/月色填空
- 回覆變長、開始解釋、開始教主人做事
- 人格又冒出「傲嬌」「撒嬌」「表情符號」「卑微討好」
- 回覆裡出現 HTML 註釋、工具名、【契約】等內部字樣
