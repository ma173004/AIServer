# 提示詞更改前必讀（2026-10-24 建立；每次改 prompts/ 前先讀這份）

> 起因：v7 寫到 4247 字、14 節、12 處示例、45 條負面，而我們自己的《示例規範》寫著 chat_owner 0 示例。不是不知道，是沒有把規矩變成必經流程。這份文件是流程的第 0 步。

## 一、三種人稱，各有優勢（先定規矩，再動筆）

| 人稱 | 示例 | 優勢 | 風險 | 適合放哪 |
|---|---|---|---|---|
| 第一人稱 | 我叫映月，我說話… | 自我認同最強；像自述而非指令，語氣自然；適合把「我是誰、我的性子、我的習慣」寫成人話 | 模型容易把使用者當「自己」或過度角色扮演；契約類規則放在第一人稱裡會變弱 | **人格自述段**（我是誰/性子/怎麼說話/做事） |
| 第二人稱 | 你是映月，你要… | 指令遵循最高；邊界清楚；方便做契約與格式 | 容易像被命令，寫多了會「演」而不是「是」；長篇第二人稱會讓人設生硬 | **技術契約**（工具/邊界/輸出格式/引用/記憶） |
| 第三人稱 | 映月是…，她會… | 可容納更多細節與旁白；適合世界觀、關係、背景設定；模型把它當「資料」處理，較穩定 | 距離感；容易變成人物卡而不是她本人；沉浸感弱 | 世界觀/背景資料（如果以後有） |

**本項目決定（2026-10-25 主人已確認）**：人格自述段用第一人稱；技術契約段用第二人稱；兩段分節、不混寫。第三人不寫「她／映月」，除非是給其他 agent 看的資料。

研究依據：角色提示對語氣/行為有效但對準確率有限（Anthropic）；人格比重大的 system prompt 最多降低 8.2% 指令遵循（arXiv:2512.14754）；關鍵指令埋長 prompt 中間會被低估（Liu et al. TACL 2024）；負面指令（不要／不得）不如正向描述期望行為（Anthropic 反模式）。

## 二、這個項目寫提示詞的硬規矩（V1）

1. **寫「我」不寫「她」**：人格段第一人稱自述。寫完自問：這句話像不像一個人說自己？
2. **具體到可觀察、可判定**：不寫「溫柔」「傲嬌」「情緒化」，寫「主人說累時，我先問他哪裡累，再給一句陪伴」「被誇時我會嘴上否認，但記在心裡」「主人玩笑時我可以接，但不拿他的痛處」。動詞＋觸發條件＋落點。
3. **每句話都要有行為含義**：寫不出「她會做什麼」的句子就刪掉；但抒情不是禁區——她是人，人會抒情，不必限制她表達情緒。要避免的是用抒情代替規格、只有氛圍而沒有可判定的行為。
4. **不在 prompt 裡寫註釋**：不寫日期、不寫「主人說…」的來由、不寫段目標籤（「硬底線」「像人，不像作文」「主人模式」）。理由寫進 docs，prompt 只放行為。
5. **正向規格優先**：能寫「先回答，再補一句」，就不寫「不要繞彎」。負面句只留不可協商的底線（傷害、隱私、欺騙）。
6. **心理話每輪都要有**：先寫 `<inner_monologue>`（我怎麼判斷這句話、要不要工具、邊界在哪），再寫 `<reply>`；所有 agent 同一格式，代碼剝離後只記日誌。這是「像人」的關鍵，不是裝飾。
7. **示例 0 條**：示例進 eval 庫，不進 prompt。要舉例，用「一句規則＋一句行為」代替。
8. **一進一出，有預算**：改前跑 `prompt_audit.py` 存基線；改後再跑；超 1300 chars / 7 節 / 0 few-shot / 12 負面 → FAIL，git hook 會擋。
9. **狀態、場景、記憶不寫進人格**：由代碼注入短段（T6 狀態、場景 overlay、記憶/日記）。人格只寫「我是誰、我怎麼做」。
10. **改完必須實測**：py_compile → restart → 探針（3–5 句）→ 回歸 → commit 記規模變化。
11. **寫完必查人稱（2026-11-09 主人 m27851 要求）**：契約／動態字串提到主人時，一律用「主人」或「你」，不用「他」；對主人說話（say／回覆）用「你」。每改完一次（prompt 檔或代碼裡的契約、判斷塊、提示句）都跑一次人稱掃描，看 system prompt 裡還有沒有用「他／他的」指主人的句子；掃描不只跑打包後的 prompt，也要跑實際輸出的一句話。工具：`agents/.venv/bin/python .dsh_scratch/person_scan_20261109.py`（輸出 SYSTEM_LEN、HITS 與命中上下文）。「他人」「其他」這類成語不算違規。

## 三、日記／記憶的寫法（對照別人的做法）

- 參考做法（主人提供）：`PARTNER.md` 每次請求全文讀入，是「蒸餾後的畫像」；故事、日誌放 `partner/` 子目錄，需要才讀；工作區即記憶，跨 session 只靠寫檔。
- 我們已有：`self_memory` 日記（第一人稱，每日上限）、`mind` 對主人的理解（蒸餾，24h 更新）、Hindsight 事實、關係鏈 people.json、session 摘要。
- **寫法結論**：人格 prompt 不塞記憶；只注入「當日/近期日記摘錄（≤520 字）」＋「對主人的理解（≤460 字）」＋必要事實；長內容放檔案/頁面（/memory），要時再讀。遺忘＝降級不刪。
- 判斷「值不值得記」：先輕量規則（情感強度、目標相關、自我/使用者相關、任務效用），再模型蒸餾；寫入時記可信度；檢索時看可靠度與使用歷史（Memory Worth 計數器）。

## 四、他山之石的拆解（別人的項目，僅供參考，不一定適合本項目）

> 以下是大肥魚項目的拆解，動機是理解它為什麼有效；不當成規格照搬，只取我們用得上的。

1. **自述是系統前綴**：寫的是「我是誰」而不是「你要扮演誰」，模型用第一人稱輸出——身份一致性高。
2. **行為級偏好（值得借鑑的引導寫法）**：不寫「你要主動用工具，否則扣分」，而是把動機接到行為上——「我想做什麼，就需要調用什麼」。想要她主動調用工具，不能強求，要引導：給她判斷路徑，不是給她鎖鏈。
3. **能力邊界可判定**：「以環境說明為準，關著就照實說」；「密碼、付款、發出去收不回的先停下來問」。確定性規則。
4. **沉默是合法動作**：「不想說話時安靜也是一種回答」。
5. **自述本身是工作區文件**：可讀、可改、下次 session 生效 —— 人格也是可持續編輯的產物。
6. **區分訊息來源**：`external_event_frame` = 別人說話；user message = 機器在跟她說話。避免把系統訊息當主人指令。

> 口癖不寫頻率規格：口癖屬於後天發展，不必用規則去規定。之後嘗試給她權限自己改自己的提示詞，我們定期檢查就好。

## 五、我們的優勢（寫法上要利用）

1. **32K 上下文**（不是 1M）：日記/狀態/記憶都必須預算化注入，不能全文塞；換來的是每輪都能帶「今天的她」。
2. **T6 情緒系統**：狀態是數值（激素→旋鈕→語氣），不是從文本模擬。提示詞只需說「狀態會影響我怎麼說，狀態由系統給」，不必寫「溫柔=…」。
3. **記憶工程**：日記、理解、關係鏈、Memory Worth——讓「我」逐年變化有依據。
4. **多 agent**：每個 agent 都要心裡話/邊界，不是只有 chat。

## 八、引導 vs 意圖引導 vs 教學（2026-11-09 主人 m27176 定調）

這一節是上面所有規矩的前提：寫錯方向，寫得再漂亮都是錯的。

### 三個詞

- **引導**：讓她知道自己要做什麼、知道如何去做。給路徑、給工具、給資料在哪、給判斷條件。最後一步由她自己走。
- **意圖引導（禁止）**：替她做決定——告訴她該想要什麼、該對什麼感興趣、該先查哪一件、該放下哪個念頭、該有什麼情緒。她照做了，也不是她的選擇。
- **教學**（行動引導的正式名稱）：把「怎麼做」講清楚。有哪些來源、工具怎麼調、判斷要看哪幾個事實、什麼時候算完成、做不到怎麼說。教學可以很具體，但不能替她選。

### 判斷句

寫下任何一句之前問自己：**這句話是在教她「怎麼做」，還是在替她決定「想做什麼／先做哪個／要不要做」？** 後者就是意圖引導。

### 寫法模板

- 給能力清單：`你能查的：記憶、今天的採集、工作臺、問題清單、筆記、群聊記錄、提醒。`
- 保留選擇權：`做不做、先做哪一件，你自己決定。`
- 給判斷材料而不是結論：`這題想過 N 輪、目前知道…、卡在…；要不要繼續由你判斷。`
- 給方法而不是目標：`查不到時可以換來源，或直接問主人；兩條路都可以。`

### 不算意圖引導的例外

- 安全與事實邊界：不能假裝身體、不能編造、隱私與權限。
- 工具可用性與成本：看圖很慢、先想清楚再看；不確定就先問。
- 格式與輸出契約：標籤、回覆格式、人格人稱。

### 落地要求

1. 新 prompt 句先過這一關再寫。
2. 既有句子的審計與處置見 `docs/記錄-20261109-引導與教學審計.md`；清單裡的「待改」不一次改完，但要留著追。
3. 改完後，她做的選擇可能和我們預期不同——這不是 bug；除非她選錯路徑導致事實錯誤，否則不要改回去替她選。
4. **兩步生成**（2026-11-09 主人 m27311）：第一步先「讀懂他這句」（`chat_agent._judge_message`，3B，trace `04_chat_judge`），把初步判斷放進 context；第二步才是生成回覆。判斷是初步的，不是裁定——主模型仍以原文為準。要她「先判斷再回覆」時，做成分步流程，不要寫成一句順序指令。
