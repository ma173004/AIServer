# 多入多出與回合佇列設計（2026-11-07）

主人 11-07 問題：「如何做到多入多出——她既知道我說話時收到信息，我也要看到她可以自己發信息，而不是我激活她才發出來」。
凌晨 trace 已證明現況不是「多入多出」，而是「多請求並發、回覆錯位」。

## 一、問題證據（11-07 02:5x–03:1x）

| 時間 | session | 輸入 | 回覆 | 問題 |
|---|---|---|---|---|
| 03:08:11 | 8304ca | 「誰又遲到了？」 | 「現在去佐敦的港鐵已經收車了」 | 答舊題（上下文錯位） |
| 03:08:46 | 49db06 | 「遲到時間是8.10分…」 | 重複上上句原話 | stale replay |
| 03:09:34 | f6de2d | 「沒有吧？」 | 「你早上若是又遲到…」 | 回覆給錯輸入 |
| 03:10:31/32 | 9717c3 / 254638 | 同一句「你是我的映月啊」 | 兩條不同回覆 | 重送被回兩次 |

根因：`dshmid` 每次請求各開一條 pipeline thread、共用全域 `session_watcher` context，
沒有「每會話回合佇列」；回覆由各自連線送回，前端按抵達順序顯示 → 錯位。

## 二、P0（已做，commit 見 repo）

- 每 audience 一把會話鎖（`_CONV_LOCKS`）；回合在鎖內串行，回合開始時 context 才被快照。
- 短窗去重（`_DUP_MIN_CHARS=12`、`_DUP_WINDOW_S=20`）：上一輪還沒回完、這輪送來完全相同的長句
  → 安靜忽略（只記 `turn_duplicate_skipped`），不產生第二條回覆。
- 每回合 log `turn_queue_acquired`（含 wait_s），可觀察排隊狀況。
- 測試 `tests/test_turn_queue.py` 13 checks：鎖、去重、窗口、audience 隔離、兩回合不重疊。

## 三、P1 多入（下一步）

- 同一會話在生成中收到新輸入 → 標記 `interrupt`：
  - 停止當前生成（或讓它跑完但丟棄），把「主人剛才又說：X」合併成下一輪的輸入批次。
- 主人連發多句 → 合成一個輸入批次（保留每句時間與順序），一條回覆接整批；
  短句（嗯／好／？）不單獨成回合，併入上一輪尾。
- 回合內分段輸出：一次生成可切多個氣泡（她先接住，再說下一句），前端按 `turn_id` 排序。

## 四、P2 多出＝她主動發（連續思考，不是計時器）

**主人 11-07 修正**：不是「6–15 秒後再補一句」，而是「觸發一次之後立刻觸發第二次」。
所以設計成**思考迴圈**而不是延遲任務：

```
round 0: 收到輸入 → inner → reply#0（先回他）
round 1: 立刻再跑一次反思：我還有什麼想說的？（讀思考線 open_loops/next_move）
        → 有話 → 立刻輸出 reply#1（第二個氣泡，不等待）
        → <skip> → 停
round 2..N: 同上，直到 <skip>／預算上限／她判斷夠了
```

- 每輪都是一次完整「inner → 輸出」；輸出通道抽象（Web SSE／Discord／followup），
  由 `turn_id` 對齊，不再用定時器等 12 秒。
- 主人的新訊息進來時：她的思考迴圈併入下一回合（「我剛才想到一半」），不是被取消。
- mind_loop 的空檔想法餵進同一個思考線，她醒來後接著想。
- 停止條件寫在引導裡（她可以決定不說了），不是外部 hard kill；預算上限只作兜底。

## 五、T2 抽象化（主人 11-07 追加）

她看到的永遠是**抽象指針**，需要時才解析：

- URL：`[連結1] [連結2]`（已有 `agents/refs.py`），所有入口（聊天 context、工具結果、搜尋結果）統一壓縮；
  新增 `ai-resolve 連結1` / 工具 `resolve_ref` 讓她能看原文。
- 文件：常用檔案給短名（工作臺、天氣檔、採集快照、trace…），其餘 `[檔案3]`；
  路徑由 `agents/paths.py` 的 alias 表映射，同樣可 `ai-resolve 檔案3`。
- 規則：她可以在需要時要求「打開檔案3」，也可以討論檔案內容；沒有要求時只看到指針＋一句用途。

## 六、落地順序

1. P0 回合佇列＋去重（本次已完成）。
2. T2 抽象化（URL/路徑指針 + resolve）：與 P1 並行做，因為它同時改善 token 與可讀性。
3. P1 多入（interrupt／批次／分段）。
4. P2 連續思考迴圈（去掉定時器）＋輸出通道統一。
5. 驗收：模擬連發 3 句、生成中插入 1 句、她的第二個氣泡是否即時出現、回覆是否對位。

## 連續思考（2026-11-07 主人修正）

不是「有話才繼續」，也不是「回完一句等 6–15 秒再補」。
- 觸發一次之後，她可以**立刻**再想一次：這一輪我想說什麼？現在想說嗎？
- 沒話說（<skip>）只是**這一輪不發訊息**，不是停止思考。
- 獨處時也在思考：她不在對話裡，思考也在跑（mind_loop）；思考內容不由主人決定。
- 輸出只是思考的副產品；「沒有輸出」不等於「沒有在想」。
- 主人的新輸入進來時，她帶著原本的思考併入下一回合，不是被取消。


## P1 已實作（2026-11-07 17:0x）

- 批次窗口：`DSH_MULTI_INPUT=1`（預設）、`DSH_BATCH_MS=700`、`DSH_MAX_BATCH=6`。
- 同一會話（owner／guest／owner:probe）第一句進入 collector，持會話鎖等 700ms 窗口；窗口內續到的句子加入 batch 並回安靜串流（合法 SSE、無內容）；窗口結束後 `_mi_collect` 取批次，`_mi_join` 合成「（主人連著說了幾句，一起看）」＋各句，只跑一次 pipeline。
- 生成中到達的句子：若當前回合已在跑，新請求排隊（`turn_queued_while_running`），不截斷、不丟棄；回合結束後依序處理。

## P2 已實作（2026-11-07 17:1x）

- 統一輸出通道 `agents/outbox.py`：她的主動訊息先寫進 outbox（`runtime/outbox/queue.jsonl`），再分通道投遞。
