# 多出量測（cycle ledger）與 followup 去重 — 2026-11-17

主人 m43067 的定義（原話）：「多出是一個思考的延續…可以不同話題、不同目的；這個多出不一定要是一個固定的流程，而是一次主動輸出……我們一直在做的循環思考就是這個目的……一次循環思考就是（一次多出）……出、入、思考最終要合併成一條線，而輸出與輸入不過是這段循環思考的一個出入點。」

今晚先做的是**量測**，不是改行為。兩隊紅隊一致：先 write-only instrumentation 3–5 天；不要現在把 cycle/event 合併成一套治理架構，也不要改 180/120 秒或加 proposal→policy。

## 二、3–5 天要看的指標（預註冊）

每天 L0 對帳 + cycle ledger 統計：

- H1（新證據比例）：≥50% 的 cycle **沒有**新 evidence（`evidence_ids` 為空）→ 說明多數循環在內部打轉，不是「有東西想說」。
- H2（真正可見多出）：實際送到主人、且與前 24h 無重複的輸出 < 5 條/日 → 多出問題主要是日誌重複與通道，不是話太多。
- H3（節奏不是解）：把 idle 間隔從 1800 改 600（shadow 模擬）不會提升「延續率」或「有證據比例」。
- H4（研究 vs 相關）：paper signal 的 cycle novelty 高、owner relevance 低；如果這比例 > 60%，先修生成契約與 route，不是加通道。

輔助指標：延續率（同 thread/open loop）、模板率、克制率（該空而空）、stale（重提已閉合）、研究外洩、送達重複率、主人回覆率。
驗收線：同一腳本兩次結果一致；能解釋 >=90% 的重複組；抽 30 輪人工標註一致率 >=90%；>20% 無法歸類就停，先修分類。

## 三、「延續＝同 thread／open loop／明確橋接」不可行的狀況（主人要求）

1. **同 thread 也可能換話題**：thread 是容器，不是語義；她可在同一個 thread 裡開新問題 → 操作化過寬。
2. **不同 thread 也可能是延續**：私聊→群、紙條→對話、跨天同一項目 → 過窄、漏接。
3. **open loop 可能只是她自己認為開著**：她可能已用紙條閉合、或主人沉默不是答案 → stale 重提。
4. **open loop 可能從未對主人說過**（私人紙條）→ audience 混線、把私事當延續。
5. **「明確橋接句」會變文體模板**：「對了，之前你說…」每句都要橋接 → 機械化、像客服。
6. **沒有橋接句但延續很明顯**：短句「嗯，那時你…」也能延續 → 誤判為非延續。
7. **同 thread、不同目的**：研究進度 vs 關心 vs 抱怨 → 同 thread 不等於可說、該說。
8. **長期 thread 沒有自然結束**（睡眠、工作項目）→ 永久延續，變成無限堆積。
9. **多個 open loop 同時活躍**：延續對象不唯一，模型選一個可能選錯（thread A 的話接到 B）。
10. **主人離開/沉默**：延續變單方面堆積（之前 5–6 條的主因）→ 需要「是否已送達/是否被接住」信號，不只是 thread。
11. **延續的記憶本身可能是假的**：例如「圖書館第三排」是研究內容被當成經歷；延續會把假記憶說得更真。
12. **thread id 不穩**：重啟、壓縮、session 重建後 id 可能消失 → 操作化不可重現、不可跨進程回指。
13. **語義延續沒有客觀標籤**：人工標註成本高、κ 可能很低；不同人對「延續」判準不同。
14. **用 bigram/embedding 相似度判延續**：會把重複當延續、把新的不同見解當不延續；而且她的研究語句長得很像。

結論：thread/open loop 可以當**輔助特徵**，不能當唯一判準；真正缺的是「這次輸出有沒有新證據／是否已送達／是否已被主人接住」的客觀記錄。這也是先做 cycle ledger 的原因。

- `evidence_ids` 目前只含本輪 act 結果；external events（HKO/MTR/collector）還沒接進來，所以 H1 會低估「有新證據」的 cycle。

- `cycle_id` 目前是「session+reason+毫秒」的 chain id；重啟後不連續，適合單輪分析、不適合跨天 join。
- after_turn 已停發，所以 `decision=emitted` 的 after_turn 應該接近 0；若看到非零，代表 emit_after_turn 被手動打開。
