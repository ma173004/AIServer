## 一、今晚真實信息實測（重要證據）

種子（主人本人提供）：名字馬君霖、男、2008-08-24 出生、香港永久居民、出生深圳、學生、麗澤中學 6C、優點邏輯強、缺點自卑/成績不好/直來直往不善交際、喜好待她慢慢總結。
寫入 master（`kind:owner_fact`，5 條）。

實測結果：

| 問題 | 回覆 | 事實是否注入 |
|---|---|---|
| 我叫什麼名字？ | 你的名字是馬君霖。 | ✅ 命中 |
| 我生日是哪天？我今年幾歲？ | 我沒有記住你的生日和年齡 | ❌ 未注入 |
| 我讀哪間學校？ | 我沒有記住你的學校 | ❌ 未注入 |
| 我有什麼缺點？ | 我沒有記住你的缺點 | ❌ 未注入（decompose 連 memory_retrieve 都沒填） |
| 還記得我喜歡什麼嗎？ | 你喜歡雨、書和音樂 | ⚠️ **幻覺**（種子沒有喜好；這是編的） |

根因（已定位到代碼）：
1. **`memory._relevant()` 字面 bigram 過濾太嚴**：查詢「生日」與記憶「2008年8月24日出生」沒有共同 2 字片段 → 被當無關丟掉；「學校」vs「就讀麗澤中學6C班」、「缺點」vs「自卑、成績不好」同理。Hindsight 的語義召回其實撈到了，是本地這層把有效資料濾掉。
2. **decompose 漏填 memory_retrieve**：「我有什麼缺點」是問主人屬性，卻沒觸發檢索（`should_recall` 因此回 False）。
3. **寫入是異步抽取**：`retain(wait=False)`，種子寫完 22 秒內還沒抽取完 → 立即召回會漏（維護/種子腳本要 `wait=True` 或等 operation 完成）。
4. **幻覺兜底不足**：記憶沒命中時仍編「喜歡雨、書和音樂」；誠實守門目前只守「還記得」句式與行動宣稱，守不住屬性問題。

## 二、上下文結構診斷（現狀問題）

以最新 trace `05_chat_prompt` 為準，現在一輪的 user message 組成：
`【当前状态】→【提示】→【历史摘要】→【最近对话】→【這輪不要重複】→【話題狀態】/【上一輪你問過】→【历史记忆】→【当前输入】`

問題清單：

1. **事實與元指令混在一起**：摘要、禁句、話題提示這些「怎麼做」的內容，和「事實」同層灌進 user message；小模型分不清「這是資料」還是「這是命令」。
2. **摘要與最近對話重複**：摘要本身就是最近對話的概括，history 有 8 條時同時注入＝同語義出現兩次；矛盾時模型傾向信摘要（摘要又是 3B 寫的）。
3. **記憶不是「開箱即用」**：注入是一句句原文＋`[m:id]`，沒有「這是什麼／何時／誰說／可信度」；模型還要自己解析，且 `_filtered_mem` 只按字面去重、截 4 條，不分主次。
4. **注入長度波動大**：同一輪 context 348→1200 字跳動；system 裡的時間/情緒每輪變，前綴緩存幾乎失效。
5. **工作臺/話題/禁句都在尾端**：越靠近當前輸入的越被模型重視，但尾端塞的是元指令，會擠掉當前輸入的注意力。
6. **沒有分區預算**：各段沒有 token 上限，長了就互相擠；也沒有「本輪有效資料是否齊全」的檢查。

## 三、上下文結構 v2（建議設計，明天拍板後動工）

**分層原則：靜態的放 system，事實放固定區，指令不跟事實混。**

```
system（≤1500 字，跨輪不變優先）
  人格（chat_owner_v9）
  契約（輸出格式/記憶/下一步/工作臺/推進）
  場景 block（一輪最多一個，S1–S9）
user（順序固定、各段有預算）
  【時間】一行（只留現在時間/情緒/場景，不放長狀態）
  【事實卡】≤300 字（見第四節：3 條以內的短事實，帶時間/來源）
  【對話】≤1200 字（最近 8 條，帶 [HH:MM] 發言者；摘要只在 history < 4 條時注入，且標「摘要，可能有誤」）
  【當前輸入】原話
```

另外：
- 把「這輪不要重複／話題狀態／上一輪你問過」合併成**一行行為提示**（例如「這個話題 18:20 聊過，先確認有沒有新情況」），放在【對話】之前；沒有重複就不出現。
- 工作臺改成 system 常駐（內容短、只在有內容時注入），不進 user message。
- 摘要注入策略：history ≥4 條時**不注入摘要**（重複且失真源）；新會話 history 空時才注入，並在摘要前後標「以下是壓縮記錄，可能有誤，優先用【事實卡】」。

## 四、記憶沉澱層（新，明天設計啟動）

現在只有「寫入→召回」兩段，沒有中間層。目標：**召回就是答案，不是材料。**

三層：
1. **事實卡（fact_cards）**：`主語-屬性-值-時間-來源`，例如
   `馬君霖｜生日｜2008-08-24｜2026-11-01｜主人自述`
   寫入時抽取、同 key 合併去重、衝突保留最新並標註、過期標記。
2. **畫像（profile）**：她對主人的「總結」——喜好/厭惡/擅長/缺點/習慣，由她從對話與事實卡慢速寫（每週一版，主人可審）；這正好對應「喜好我自己都不知道，得讓她慢慢總結」。
3. **召回投影**：query → 挑 1–3 張卡 → 改寫成一句話注入（「你生日是 2008 年 8 月 24 日」），不再注入原文句子；沒有卡就明確說不知道，不編。

落地順序：①先修 `_relevant` 過濾與 decompose 漏檢索（明天的 P0，一天可完成）②再建 fact_cards 與沉澱 job ③最後做召回投影與 profile。
