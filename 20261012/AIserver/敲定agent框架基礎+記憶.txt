一、总体定位
不是"工作流 vs agent"，是"每步的粒度"。

三层结构：

text
总管（dshmid 调度层）
  ├─ 接收 / 拆解 / 路由 / 融合 / Q3 / 输出
  └─ 不管 Agent 内部怎么做

Agent（7 个）
  ├─ 自己的 prompt + 业务规则 + 技能注册表
  ├─ 内部拆解 + 执行循环
  └─ 出片段

技能（skill）
  ├─ 具体操作步骤
  ├─ 自带工作记忆（Hindsight 知识摘要）
  └─ 遇突发事件自主处理
原则：总管不管 Agent 内部怎么做。

二、7 个 Agent
Agent	职责	产出物
chat_agent	闲聊、情绪回应	纯对话
task_agent	做事类（工具调用）	动作结果
writing_agent	长篇写作	长文本
learning_agent	学习输出	知识结构化
research_agent	资料检索整理	资料包
code_agent	代码相关	代码 + 说明
generic_agent	兜底	通用
允许"一输入多 Agent"。

三、8 阶段流程
text
阶段 0：接收
  输入：原话 + 最近对话 + 跨对话项目上下文
  动作：Hindsight recall 查进行中项目

阶段 1：拆解（1×LLM）
  识别：子任务 / 潜在需求 / 风险 / 模糊点
  产出：subtasks + 建议 Agent + fusion 策略

阶段 2：不确定性分流
  真模糊 → 追问（4 维度判据）
  潜在需求 → 转 subtask
  风险 → 加 subtask

阶段 3：调度
  按 depends_on 排序 + 识别可并行
  按工具调用数量粗排（差距大 → 短的先输出）

阶段 4：执行子任务
  每个 subtask → 对应 Agent
  Agent 内部：拆 → 执行 → 出片段
  含 5 种回流 + 5 种动态创建

阶段 5：收集片段
  {slot, 内容, 状态}

阶段 6：融合（规则判，不调 LLM）
  separate / fused / main_first

阶段 7：Q3 润色
  1 份基础 prompt + Agent 参数注入
  皮不变（映月）

阶段 8：异步归档
  retain 到 Hindsight
  更新跨对话项目状态
  记录成功的子任务 + 调用的 skill
四、5 种回流
回流类型	触发条件	drift	谁执行
Local Repair	结果不完整，换关键词/工具	< 0.3	Agent 自己
Sibling Notify	影响兄弟任务	任何	Agent 通知调度器
Global Replan	子任务定位错了	0.3-0.6	回拆解器
Reactive Exploration	方向根本错了	> 0.6	总管重选 Agent
Cross-Session Resume	跨对话项目恢复	—	阶段 0/8
关键：Sibling Notify 不是 Repair。 它不修自己，是通知别人调整。

七、预算（两级）
text
Agent 级：
  最多 5 个任务名额（主任务）
  每个主任务内部最多 5 个子任务
  每个子任务可延伸 2 层（子子 + 子子子）

结构：
  主任务 1（= Agent 收的这个）
    × 5（子任务）
    × 2（子子任务）
    × 2（子子子任务）
预算衰减：

每调一次 LLM，扣 1 额度

prompt 里告诉它"你还剩 N 个"

用完 → 强制收敛

时间统计延后： 跑够次数再统计。

八、Checkpoint
时机
时机	存什么	成本
每个 subtask 完成	全量	中
每个 step 完成	增量（execution + budget）	低
每个工具调用前后	增量（tool_calls）	低
回流请求审批后	增量（reentry_history）	低
用户打断时	全量	中
定时（每 30 秒）	全量	中
策略：

全量：只在关键节点（subtask 完成 / 打断 / 回流）

增量：每步都存

恢复：最近全量 + 之后的增量重建

存什么
text
- 任务图
- 执行位置
- 预算状态
- 工具调用幂等性记录
- 记忆上下文
- 回流历史
- 已收集片段
九、打断恢复
text
打断时：
  1. 正在跑的工具调用 → 继续跑完（外部 API 不能取消）
  2. 当前步骤完成 → 保存 checkpoint → 状态 = waiting_user
  3. 新用户输入到达 → 判断：
       同任务补充 → 合并到当前任务，恢复
       新任务 → 询问旧任务是否继续
               若继续 → 问先进行哪个
  4. 15 秒无输入 → 从 checkpoint 恢复
和 ASTRA 打断机制一致。

十二、输出节奏
立即确认
text
T+0s: "收到，我看下"    ← 映月模板
分段输出
text
T+0s:   "收到，我看下"           ← 模板
T+15s:  "读了代码，找到一处要改"   ← 里程碑
T+30s:  "改完了，代码发你"         ← 里程碑
T+45s:  "改动点有这些……"         ← Q3 润色
T+60s:  "为什么这么改……"          ← Q3 润色
调度规则
规则	动作
距上次输出 > 15 秒 且 有可输出内容	攒批输出
遇里程碑	立即输出
可输出内容累计 ≥ 3 条	输出
speakable 机制（暂缓）
Agent 标记哪些 think 内容可输出。先跑主任务，后续做。

十三、验证（三级）
text
Level 1: URL 格式合法 → 通过
Level 2: 本地缓存有记录 → 通过
Level 3: curl 能 200 → 通过
Level 3 失败 → 标记 "未验证"，不阻塞输出
URL 缓存存临时文件。
