# 醒來＝讀工作臺：修正設計（待主人確認再動工）

日期：2026-11-06
修正版，取代 `docs/設計-20261106-醒來時的自我重建.md` 裡「另造 wake.json／who.md」的設計。

## 一、工作臺就是喚醒（修正）

我原本把「醒來」做成新檔案，是錯的。工作臺已經是她每次被調用時最先看到的自己的東西：上次做到哪、下一步、最近結果。**她讀板的那一刻，就是她重新拼自己的那一刻。**

- 工作臺第一節改為「醒來」：上次到哪、留給下一次的話、她現在的狀態一句（用她的話，不寫激素）。
- 下面才是「正在進行／下一步／最近結果」。
- 每次回覆前，她先讀工作臺（我們自動注入 700 字摘要，不用她調用）；回覆後，她更新「醒來」節：
  - 這次接到哪裡、什麼還沒說完（給下一次自己的話）；
  - 她正在成為什麼樣子的一兩句（不是日記，不寫流水帳）。
- 不另造 wake.json；「醒來」就是工作臺的第一頁。

## 二、關係、稱呼：她可以自己改

工作臺（或它的附頁）分兩段：

- **HAND（主人給的，永不自動改）**：她的名字是映月；主人是誰；紅線（不假裝身體、不編共同經歷、不洩漏隱私）。這段我跟主人都可以改，但她不能改。
- **AUTO（她自己寫、自己改）**：她怎麼稱呼主人（現在是「主人」，以後可以是她自己選的）；她怎麼看這段關係；她希望主人怎麼叫她；她在意什麼、討厭什麼。她可以改寫，並留一句為什麼改。
- 我提供起點一行，其餘她自己長。每次改動記版本，主人可查看。

## 三、KV 緩存與注意力層：分清哪層是誰做的

| 層 | 是誰的 | 對我們的約束 |
|---|---|---|
| 分詞、embedding、注意力層、KV 緩存 | llama 原生（llama.cpp/ollama） | 提示詞只能改「輸入的 token」；不能直接改權重或注意力。能動的只有溫度、logit_bias 這類解碼參數 |
| 前綴 KV 緩存（prompt cache） | llama 原生 | 前綴越穩定，複用越多；**每輪改 system 前綴＝整段重算＝變慢** |
| system／user 提示詞分區、動態內容順序 | 我們（提示詞） | 固定內容放前綴（人格、契約、場景）；每輪變的（【對話】、碎片、醒來重建）放 user 分區尾部 |
| T6 行為限制（句數、主動性、要不要提問） | 我們（代碼層） | 不出現在提示詞裡，直接限制她的回覆形狀 |
| 「我現在的狀態」 | 她生成的 | 由醒來步驟從碎片裡生成成一句話（user 分區），不是我們把激素寫進 system |

所以 T6 的位置是對的：**不是把狀態寫進 system，是①行為層由代碼限制②醒來時她自己用話說出「我現在的樣子」。** 我之前把「醒來重建」往 system 塞，會破前綴緩存，也把狀態變回台詞；改成放 user 分區尾部、只有一行。

## 四、32k 上下文下的人格蒸餾：分層＋增量，永不把原料塞進上下文

- **L0 原料**：session_log、思考線、反思、工作臺、Hindsight 記憶。永不進上下文；它們在硬盤和記憶庫裡。
- **L1 候選**：每天（或每輪）用 14B 對「單次對話／單個來源」抽 3–8 條候選，帶源指針（哪一天、哪一句附近）。一天的材料一個 14B 調用就能讀完，不爆 32k。候選存 `runtime/self/candidates/`，等主人或每週合併。
- **L2 人格檔**：≤200 行／6000 字，五段（原則／場景／我怎麼活／判斷／我該少說）。每週合併一次：只讀「上一版 L2＋這一週 L1」，**不重讀 L0**。合併用 claude（品質），抽取用 14B（量）。
- **L3 運行時**：聊天只看到 L2 的一小段（≤120 字醒來句）＋工作臺摘要。L2 全文只在蒸餾時用，不進聊天上下文。
- 素材哪來：不用外部素材；就是她自己的對話、反思、工作臺、記憶沉澱。我們的 pipeline 每天自然產生。
- 成長而不是定型：L2 每一版是「她讀了自己的新經驗後改寫的自己」，不是一次定型的性格；改動有版本、可回滾；HAND 段不動，AUTO 段她改。
- 上限保险：L1 每週不超過 200 條；L2 超過 200 行就淘汰最舊、最不像「她」的條目（淘汰判準也由她寫在 L2 的「我該少說」旁邊）。
