# 復述：P06／P28／P29／P30／P31 的名詞與落地步驟

用途：讓主人不用翻代碼就能核對「我們到底要做什麼」；也給紅隊第三輪證反。
這份文件不是新方案，是把 v2 計劃翻成日常語言，並把每個名詞對應到現有程式與資料。
今晚只做 P06 Phase 0 的 shadow（只記錄、不改回覆行為）；P30／P31／P28／P29 只做離線 fixture 與報告。

## 一、先說「shadow」和「candidate」是什麼

- **shadow（影子）**：程式照常回覆，只在旁邊多寫一份紀錄。主人看到的回覆完全不變；用來量「如果照這個規則做，會發生什麼」。shadow 不是上線，也不是 A/B 測試。
- **candidate（候選）**：shadow 的資料符合驗收線後，做成一個可開可關的開關（flag）。預設關閉；要主人簽字才開。
- **production（生產）**：主人實際使用的路徑。今晚不碰。
- **全量回歸**：跑 `bash scripts/run_all_tests.sh` 的所有測試群組；目標 0 FAIL，並在重啟後看 health。不是只看新功能，是確認沒有把舊功能弄壞。

## 三、P06 的具體步驟（今晚唯一會寫程式的地方）

### Phase 0：只記錄，不改行為
1. 在 `agents/dshmid.py` 現有的 `_msg_attr` 旁邊，擴充事件格式；**不新增第二個 ledger 檔案**。
2. 每條入站訊息先寫一筆 `received`：`msg_id`、`text`（最多 500 字）、`channel_id`、`audience`、`session_id`、`reply_to`、`ts`。
3. 被合併時寫 `collected`／`merged`：帶上 `turn_id`、`msg_ids`。
4. 生成前寫 `generating`：`turn_id`、`owner_msg_ids`。
5. 回覆完成寫 `answered`：`turn_id`、`reply_msg_id`、`answered_msg_ids`。
6. 若某條訊息在這輪結束時仍屬 queued／沒有被 collect，寫 `carried` 或 `lost` 候選；若之後被下一輪接收，再補 `answered`。
7. `_mi_finish` 不改清除行為；只多寫一筆 `finish_shadow`：這次它實際清了哪些 `turn_id`／`msg_ids`，以及「如果 owner-scoped，會留下哪些」。這是 shadow 的重點。
8. 新增 `scripts/turn_accounting_report.py`：讀 ledger，輸出每個 msg_id 的終態、unaccounted、lost、carried、duplicate、stale。先對 00:44–00:47 四條做 replay。
9. 測試：單元測試 ledger 寫入與終態；用 00:45 四條 fixture 證明三條 lost 能被 accounting 算出來；不改任何回覆。

### Phase 0 驗收
- 四條 fixture 的 accounting 100%（每條有終態）。
- 現有回覆行為 0 改變（跑前後 diff，或關掉 ledger 時完全一致）。
- 全量回歸 0 FAIL。
- 不在 production 開任何 flag。

### Phase 1（只有 Phase 0 兩天全綠才做）
- 真正的 owner-scoped finish：只 finalize 自己的 `turn_id`。
- queued 訊息以 `carried` 併入下一輪 context；一輪仍只回一條；超過一輪用一句承接；太舊則 `superseded`，不發話。
- 測試 30 個合成 burst；驗收 accounting 100%、lost 0、duplicate 0、stale ≤1/20、氣泡 ≤1.05×。
- 任何 HTTP hold >30 秒或未記錄終態即回滾。

## 九、請紅隊證反的五個點

1. P06 ledger 的事件格式是否真能重建終態？`received` 存原文但 `_mi_begin` 仍不存 queued text，Phase 0 的 accounting 會不會只是把 lost 記得更清楚，而不是修好？
2. `finish_shadow` 只記錄不清除，是否足以證明 owner-scoped finish 安全？有沒有更小的 shadow 辦法？
3. P30 的 evidence ledger 會不會又變成第二個 shadow？哪些來源不該進？
4. P31 的「必要澄清」反事實判定，會不會在主觀題上不可判定？16 條分類是否會變成我自己的判斷？
5. P28 的 C 臂把主人後續解釋放進 context，是否等於用未來的資訊作弊？這樣測出的提升有沒有意義？
