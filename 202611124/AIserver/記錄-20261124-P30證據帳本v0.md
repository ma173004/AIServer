# 2026-11-24 P30 證據帳本 v0（只記錄、不 enforce）

## 目的

她會說出「7 個欄位」「47 分鐘」「洗澡後語速變慢」這類沒有工具或原文依據的具體事實。P30 先不修回覆、不做 claim checker，只建立可核對的帳本：**這一輪實際注入到 context 的每個區塊是什麼、長度多少、內容 hash、來源是哪個子系統**。

紅隊（sys-2 第三輪）的約束：
- 在預算裁剪**之後**記錄，只記真正留下的區塊。
- 不自己 collect facts；解析最終 context 字串，避免「ledger 有、prompt 沒有」的假支持。
- 只存區塊名、長度、hash、來源標籤，不存原文。
- 任何錯誤都不能擋回覆。

## 實作

- 新 `agents/evidence.py`
  - `PATH = runtime/shadow/evidence_ledger.jsonl`（env `EVIDENCE_LEDGER_PATH`）。
  - `ENABLED = env EVIDENCE_LEDGER=1`（預設開；`0` 可立即關）。
  - `split_sections(context)`：按行首`【...】`切區塊；第一個區塊前的文字記 `preamble`。
  - `record_context(session_id, user_input, context, history=None, extra=None)`：
    - 每區塊記 `{name, source, chars, sha(16), msg_ts?}`。
    - 每輪記 `{ts, session, user_sha, context_chars, sections, v:1}`。
    - 不記 context 原文、不記 user 原文。
    - 永不拋例外；寫入失敗回 None。
  - `recent(limit, session)`／`stats()`。
- `agents/agent_mod/chat_agent.py::_process_impl`：context 拼好後、`05_chat_prompt` trace 前呼叫 `evidence.record_context(...)`；`_test_mode_active()` 時跳過，避免測試污染。
- 來源對照：`clock`／`rule`／`reply_context`／`owner_snapshot`／`self_activity`／`judge`／`hko_weather`／`fact_cards`／`workbench`／`session_summary`／`group_context`／`waiting_questions`／`reminders`／`dialog_history`／`hint`／`memory_recall`／`outbox`／`inbound_events`／`dialogue_thread`／`current_input`。
- `/shadow` 登記：`scripts/shadow_page.py::KNOWN` 與 `runtime/shadow/README.md`。

## 不做

- 不改 prompt／契約／persona。
- 不改回覆、不開 flag、不 enforce。
- 不把 evidence 寫回記憶或工作臺。

- 兩天後：數字 claim（47 分鐘、7 欄位）出現時，ledger 是否顯示「沒有工具來源」；身體 claim 是否完全無來源。
- 回滾：`EVIDENCE_LEDGER=0` → restart；已寫入的 jsonl 可保留或刪除。

## 風險

- 每輪一個 jsonl row，約 1–3KB；一個月可能數百 MB，後續需要 rotate。
- 只記區塊級 hash，不能回答「區塊內哪一句來自哪個 id」；下一步 P30 Phase 1 才做 segment/source id。
- 不 enforce 時她仍會說無依據數字；這個 ledger 只讓問題可量測，不會讓問題消失。
