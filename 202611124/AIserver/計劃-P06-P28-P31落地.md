# 計劃：P06／P28／P29／P30／P31 落地（v2，紅隊反駁後）

用途：把昨晚定位的問題與基本方向，變成可執行、可驗收、可回滾的落地順序。
版本：v2。兩隻常駐紅隊已反駁 v1；本版採用他們推翻的部分，v1 的阻塞式等待、generated anchor、claim checker、只改兩句契約、park 舊紙條全部撤回。
原則：先證據與 shadow，再 candidate，最後 production；每步有測試、紅隊反駁、主人簽字。今晚不開任何 production flag。

## 一、本週順序

1. **P06 訊息所有權（地基）**：先 ledger 與 accounting，不改回覆行為。
2. **P30 evidence ledger（只記錄）**：先建立來源，不做 claim checker。
3. **P31 問句尾巴（離線分類與三臂 A/B）**：關係回報最大，但先分類。
4. **P28 after_turn 歸因（只做測量與 context 補齊）**：不生成 anchor。
5. **P29 continuity 專案邊界（append-only paper 鏈）**：最後做，不 park、不覆寫 raw。

紅隊共識：P06 錯，其他全部會被污染；P06 的先後不是功能排序，是資料可信度排序。

## 二、P06 訊息所有權

**紅隊推翻 v1**：HTTP 內阻塞等 180 秒不可行；每 audience 一把鎖、單 worker、bot 的 to_thread 會被坐滿；超時 ack 會刷屏；「每條都回」是錯的驗收。

**Phase 0（今晚）**
- 不新增第二套真相源：擴充既有 `runtime/shadow/turn_msg_attribution.jsonl`（`agents/dshmid.py` 的 `_msg_attr`），新增欄位：
  `msg_id, text, channel_id, audience, session_id, reply_to, state, turn_id, reply_msg_id, ts`。
- 每條訊息一生只記事件：`received → collecting → merged → generating → answered / carried / superseded / failed`；事件可重建終態。
- `_mi_finish` 改成 owner-scoped：只收自己 `turn_id` 的 `turn_msgs`，不碰別人的。
- queued 訊息保存原文與時間，不再只記 id／chars。
- 不改回覆行為；夜間報表量 unaccounted、lost、carried、duplicate、stale。

**Phase 1（candidate，只有 Phase 0 兩天全綠才做）**
- 不做阻塞等待、不做每條 ack。
- 採用 **回合契約**：queued 訊息以 `carried` 併入下一輪 context（帶 author、ts、原文）；一輪仍只回一條；若超過一個回合，回覆用一句承接；過期則 `superseded`，ledger 留痕，不發話。
- 測試：4 條 DM burst、30 個合成 burst（含 3 分鐘生成、跨窗、更正、撤回）。
- 驗收：accounting 100%（每條有終態）、lost 0、duplicate 0、stale（回覆落在 >1 回合後）≤1/20、氣泡數 ≤1.05×、主人訊息→首個回覆的回合數 p95 不變差。
- 回滾：任何 HTTP hold >30s 即停；任何未記錄終態即停。

## 三、P30 無依據宣稱

**紅隊推翻 v1**：deterministic claim checker 會變第二個關鍵詞守門；「有來源 ≠ 有意義」；數字可能是推導；身體詞不能 100% 硬擋，否則變冷淡客服。

**已修正的證據**：
- 12:54「強風」是真的（HKO 強烈季候風信號 08:50–15:34），不是幻覺。
- 18:15 主人說「等我洗完澡」，所以「洗完澡」有原文，不算幻覺。
- 真正 regression：19:14「47 分鐘」、15:30「7 個欄位」、after_turn 的「手指輕微緊握」「語氣壓抑」。
- 17:22「放學後的雨」待 replay 當時 context，不先判幻覺。

**Phase 0（今晚）**
- 新 `agents/evidence.py`：per-turn evidence ledger，記錄工具結果、HKO、位置、記憶召回、主人原文；欄位 `turn_id, source_type, source_id, quote, value, ts`。
- **不做 claim checker**；先做離線 baseline：100 條歷史回覆，人工標「claim／來源／是否豁免」。
- 標註正例：強風、洗完澡、主人原話數字、正常關懷；負例：47 分鐘、7 欄位、手指輕握。

**Phase 1（只在 shadow 兩天後）**
- 只允許 **值級比對**：具體數字／檔名／時間必須等於 ledger 解析值；沒有來源或值不符，只記錄，不改回覆。
- 身體觀察：只有主人原文有才豁免；其餘 shadow，不做全域硬擋；未來若要擋，只擋「假動作／假看到」，不擋「你聽起來很累」這類語氣關懷。
- 天氣：有 HKO 結構化證據才可強制；先只 shadow。
- 量 per-category precision/recall，不用整體 5% 掩蓋某一類；另量冷淡指標（care/invite 佔比、hedge、長度、主人盲評）。
- 驗收：正例 0 誤殺、負例 recall ≥80%、care/invite 降幅 ≤20%，才談 enforce。

**Phase 0（今晚）**

- 三臂離線重放：

  * B 只加「這句是批評／不是批評」的 deterministic 標記，不生成 target。
