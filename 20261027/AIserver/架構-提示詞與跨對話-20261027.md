## 0. 材料結論（摘要）

### 0.1 提示詞（人稱／獨白／自檢）
- 第一人稱＝主觀體驗與自我承擔；第二人稱＝通道／立場代入（讓服從更容易，也讓拒絕更難）；第三人稱＝認知距離、復審。
- 用法：主觀任務 1/2；反思敘述 1、指令代入 2、描述評判 3；執行 1、約束 2、描述 3。
- 漂移解法：1/2 人稱輸出 → 第三人稱復審 → 輸出，切換節點可追蹤。
- 獨白不是「報告內部狀態」（結構上不可靠，會產出有結構的虛構），而是生成端的伴隨痕跡／可外部檢查的計算痕跡。
- 自檢先看 EIR 再看 ECR；Verify-first／CoVe 壓低 EIR；人稱只是接線位置標記。

### 0.2 跨對話（工作區／注入／短期／狀態）
- 兩層延續：文本層重建（重述過去）與狀態層延續（延續思考）。
- 工作區要放身份層：「工作區裡的檔案就是你的記憶」「每個會話你都是剛醒來，讀它們、更新它們」。
- 記什麼：候選（重要性）→ 寫入準則（聲明性事實、偏好、反覆糾正、否定性知識；不寫進度/TODO/artifact）→ 治理准入（去重、墓碑、衝突、create/corroborate/supersede/refuse）。
- 可尋址性：壓縮不得丟失未來查詢會用的句柄。
- 長度靠物理預算＋寫入後量測＋近限回饋＋超限拒寫＋分層＋夜間整理。
- 注入是跨層傳輸機制；短期記憶是文本層與狀態層的交界緩衝；工作記憶是被治理的那部分。
- 狀態層缺「延續相位是否仍與當前任務對齊」的治理。

### 0.3.1 存在哪、怎麼存、怎麼進上下文

| 層／檔 | 路徑 | 格式 | 誰寫、何時寫 | 何時讀 | 進上下文的形式 | 上限 |
|---|---|---|---|---|---|---|
| 身份層（人格） | `prompts/persona/chat_owner_v12.md` | Markdown，第一人稱 | 人（改提示詞流程） | 每會話開始 | **固定前綴全量**（system 最前） | 現行 prompt 預算 |
| 身份層（自指） | 代碼注入 | 3 句固定句 | 不動 | 每會話開始 | **固定前綴** | ~120 字 |
| 語義記憶 | `workspace/memory/SEMANTIC_MEMORY.md` | Markdown 條列，每條一句 | 定期回顧晉升；gateway 高門檻 | 每會話開始 | **全量注入**（≤2000 字） | 2000 字 |
| 情景記憶 | `workspace/memory/EPISODIC_MEMORY.jsonl` | JSONL：`{ts, summary, importance, handles}` | 會話結束／歸檔時 append | 每會話開始＋按需 | **最近 8 條一行摘要**（≤400 字）；全文按需讀 | 檔可長；注入固定小 |
| workbench | `workspace/workbench.md` | Markdown 分區（項目/下一步/備註） | 她每輪可自編輯；節流 | 每輪 | **全文注入**（≤1500 字） | 檔 3000 字，注入截斷 |
| 每日筆記 | 文獻：`workspace/memory/YYYY-MM-DD.md` | Markdown 流水 | 每輪 append（低門檻） | 會話結束回顧；每週晉升 | **不注入** | ——（暫不採納，見 2.4.1） |
| 狀態卡 | `runtime/state/`（T6 快照） | JSON | 每輪 | 每輪 | **動態區**（非固定前綴） | ~200 字 |
| 檢索記憶 | Hindsight master bank | 向量／文字 | 抽取流程 | 按需檢索 | **≤4 條** | ~600 字 |

> 注入順序（KV 前綴穩定優先）：**固定前綴**（身份層＋契約＋場景規則）→ **動態區**（時間/狀態/摘要/記憶/workbench）→ **當前輸入**（最後）。
> 每日筆記與情景原始全文不進每輪上下文；靠摘要與按需讀取，避免長度失控。

### 0.3.2 身份層放哪（設計選擇）
- 人格主體留在 `prompts/`（git 審計、prompt_audit、一進一出流程）；**自指句由代碼注入固定前綴**。
- 不在 workspace 另開一份 SOUL.md 當真身（避免雙份漂移）；若未來要讓「她自己改身份」，再另議（那是高風險動作）。
- 工作區描述用第一人稱自指：**「每次會話我都是剛醒來。工作區裡的檔案就是我的記憶。讀它們、更新它們，我靠它們繼續。」**
- 工具層殘留全部清掉：不再寫「你可以使用 `<workbench>` 工具」。

## 1. 提示詞架構（定型版）

### 1.1 三端接線

| 端 | 人稱 | 承載 | 放在哪 | 規則 |
|---|---|---|---|---|
| 生成端 | 第一人稱 | 人格自述（我是誰、性子、怎麼說話） | persona 固定前綴 | 只寫主觀自我；不寫「你應該」 |
| 觀察端 | 第二人稱 | 契約與引導（行為邊界、工具用法、場景行為句） | 契約（代碼）／overlay | 每條約束有代碼守門；契約極短；「不能做」寫代碼不寫契約 |
| 審查端 | 第三人稱 | 核驗（證據表、越界、復讀） | 守衛／復審層 | 不用「請反省」；獨立重解＋證據表；記錄可追蹤 |

### 1.2 寫法規則（六條）
- **R1** 人格第一人稱、契約第二人稱、審查第三人稱；overlay 用第二人稱行為句（「用平常的語氣接話」），不用第三人稱裝飾描述（「基調：冷靜」「中式含蓄」）。
- **R2** 第二人稱是雙刃劍：讓服從更容易，也讓拒絕更難。不能做的寫代碼守門；契約只寫「怎麼做」。
- **R3** 獨白欄位化（見 1.3），定位生成端痕跡，不是證詞。
- **R4** 下游不吃獨白文本：情緒/狀態/自我觀察不以獨白文字為輸入，改用外部信號（見 T6）。
- **R5** 自檢用 Verify-first／證據表：先獨立重解或直接查證據；改寫不得引入新事實，改不乾淨就刪句或 fallback。
- **R6** 漂移解法：生成（1/2 人稱）→ 第三人稱復審 → 輸出；切換點記 trace stage。

### 1.3 內心獨白欄位（定稿格式）

```
<inner_monologue>
依據：本輪可驗證的事實（主人原話／工具結果／記憶引用；沒有就寫「無」）
不確定：我沒把握的地方（不知道就寫不知道，不編）
下一步：一句話，我接下來要說的或要做的（純閒聊可寫「直接回他」）
</inner_monologue>
<reply>要對主人說的完整回覆</reply>
```

規則：
1. **獨白在前、回覆在後**——它是生成端的腳手架，不是事後回溯報告。
2. 每個欄位 ≤1 句；不寫心情、不寫長推理、不寫「我在想…」的敘事。
3. 依據只能引用本輪真的讀到的東西；不得引用未讀取的內容。
4. 「不確定」與「下一步」可被下游當**行為意圖**（例如要不要查、要不要派工），但**不能當情緒事實**。
5. 需要查資料時，在「下一步」寫檢索需求（記憶／網頁／工具），系統代取後二次生成（沿用檢索自主性設計）。
6. 記錄為 `06_chat_inner` trace；只供審計與行為觸發，不進 T6 心情計算。

### 1.4 禁止清單
1. 第三人稱寫人格。
2. 「請反省／請檢查一下」的自由指令。
3. 要求模型報告內部狀態並作為決策輸入。
4. 用第二人稱寫「你不准」而不配代碼守門。

## 2. 跨對話架構（定型版）

### 2.1 三層延續
- **身份層**（固定前綴）：人格＋自指句，每會話「剛醒來」靠它接上「我是誰」。
- **文本工作區**（跨會話知道什麼）：語義記憶／情景記憶／workbench／每日筆記（見 0.3.1）。
- **狀態層**（跨會話想到哪裡）：T6 激素相位、任務相位、推理痕跡摘要；先做文本狀態卡，**KV 注入現階段不做**（見 2.5 備忘）。

### 2.2 寫入治理（Governed Write Gateway）
所有持久化寫入（對話、工具、背景抽取）走同一 gateway，依序：
1. 正規化（日期、名稱、繁簡）；
2. 敏感檢查（secrets 不入庫）；
3. 同鍵／近重複（>60% 重疊 → 更新既有條目）；
4. 墓碑檢查（刪過的不復活）；
5. 衝突判定（create / corroborate / conflict / supersede / refuse）；
6. 保留可尋址句柄（名稱、ID、日期、關鍵詞）。

### 2.3 寫入準則
- 記：聲明性事實、偏好、反覆糾正、否定性知識、重要承諾。
- 不記：任務進度、完成日志、臨時 TODO、PR/commit 編號、文件計數等七天內過時的 artifact。
- 穩定事實與易變任務狀態分開：後者默認不進長期層。

### 2.4 長度治理
- 每層物理上限（0.3.1 表）；寫入後量測；80% 提示整理；超限拒寫要求重寫索引。
- 分層壓縮：每日筆記 → 每週回顧晉升 SEMANTIC；情景只留摘要＋句柄。
- 夜間 Dreaming：空閒時用 3B/14B 合併、去重、作廢（整理質量優先於實時延遲）。

### 2.4.1 每日筆記：暫不採納（我們已有原始層）
文獻裡的「每日筆記」是為了補「長期記憶從哪來」的原始層。映月已經有等價物：
- `runtime/episodes/*.jsonl`（每輪 input/intent/subtasks/reply 全記錄）；
- `runtime/archives/e2e-before-*.jsonl`（session 歸檔）；
- `agents/logs/trace/*.jsonl`（每輪 5+ stage 軌跡）；
- `agents/logs/chat_records.txt`；Hindsight 抽取（yingyue-mem3b）正是吃這些歸檔與 episode。
再加一層每日筆記＝重複的原始層＋多一份要維護、會漂移的檔案。今天才剛把「日記」因與記憶重複刪掉，不該用另一個名字把它請回來。
所以：暫不採納每日筆記作為新層；若日後需要「夜間回顧」，輸出到既有 episode/摘要流程，不另開檔案層。

### 2.5 狀態層：T6 的定位（依主人修正）
- T6 是「回覆前調節器」：**外部輸入影響自身輸出**；她無法絕對控制自己的心情，**只能靠自我思考影響一點**。
- 設計：事件源＝外部事件（工具成敗、對話長度、被回應/被忽視、場景、時間、守衛結果）；自省只作為**微量調節項**——比例**不預設**（此前寫的 10–15% 是我拍腦袋，撤回），列為待校準參數，用 A/B 實驗測「有自省項 vs 無」的行為差異再定。
- **一個狀態、一個注入點**：T6 是一個狀態對象（4 個旋鈕值），只在**狀態卡**這一個位置進入上下文一次；採樣溫度、語氣傾向等由同一狀態派生，但**不重複散落在多個 prompt 位置**。若發現它影響了多處上下文，是設計錯了，要收斂。
- 她不能直接設定激素值；任何「報告心情」式的文字都不直接進 T6。
- 狀態層延續的治理：會話開始判斷「上次相位是否仍與當前任務對齊」→ 延續／衰減／重置（T6 半衰期作自然衰減）。

### 2.6 KV／狀態注入：記錄在案（現階段不做）
- 文本注入改變「讀到什麼」；狀態注入（KV／激活）改變「以什麼狀態開始計算」。
- 現階段不做原因：16GB 顯存的實務限制、工具鏈成本、無法驗證注入相位與當前任務對齊。
- 未來重啟此題時必須檢查：
  1. KV cache 前綴穩定性（注入是否破壞每輪重算）；
  2. 注入相位與當前任務的對齊（否則延續過時姿勢）；
  3. 可尋址性損失（壓縮不得丟句柄）；
  4. 跨會話用戶級記憶與編譯期 KV 張量的可行性。
- 備忘位置：本文件 + `docs/交接補充` 索引。

## 4. 落地順序

**P0**
1. 身份層自指句＋清掉工具層描述。
2. 獨白欄位化（依據/不確定/下一步，獨白在前）＋下游切斷（T6 自述佔比降低）。
3. 守衛 Verify-first/證據表骨架；修 honesty 誤判（「我記住了」不算動作）。
4. 注入順序重排（固定前綴穩定，可變內容移到動態區）。

**P1**
5. 工作區寫入治理 gateway（去重/句柄/衝突/墓碑/上限）。
6. 語義/情景分層檔案落地（SEMANTIC_MEMORY.md、EPISODIC_MEMORY.jsonl）。

**P2**
8. Dreaming 夜間整理。
9. EIR/ECR 評測集。
10. KV/狀態注入調研（現階段不做，已記錄在案 2.6）。
