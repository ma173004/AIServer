# 記錄：記憶寫入治理＋召回句柄＋自檢 Verify-first（2026-10-27）

> 背景：主人 10-27 晚要求「行為引導殘留清理、獨白欄位化且不餵 T6、記憶/自檢細節治理（不新建層）」。
> 本輪只動既有檔案與既有數據，不新增層；全部改動附三元素測試。

## 1. 記憶寫入統一入口（既有 Hindsight，不新建層）

`agents/memory.py`：

| 函數 | 作用 |
|---|---|
| `record_write(content, kind, session_id, chunks, ok, extra)` | 所有寫入的最後一站：寫 `runtime/memory/write_metrics.jsonl`＋更新 `memory_index.json`＋更新 `last_write.json` |
| `_write_precheck(content, kind)` | 去重（指數退避：3 天內同雜湊跳過、7 天內降優先）＋墓碑過濾 |
| `tombstone_memory(chunk_hash, reason)` | 墓碑 hook：記錄 `tombstones.jsonl`，之後同雜湊寫入被跳過 |
| `memory_evidence(session_id, max_age_s=300)` | 供 honesty 的「記憶寫入證據」：最近一次成功寫入是否在 300 秒內 |
| `write_stats()` | 長度量測：`entries`、`last_24h`、`chars_avg`、`dup_skipped`、`tombstoned` |

- `remember_rounds()` 改走 `_write_precheck` → 寫入 → `record_write`；回傳值含 `metrics`。
- 量測數據：`runtime/memory/write_metrics.jsonl`（每筆：ts、kind、session、chars、chunks、ok、dup_skip、tombstone）。

## 2. 召回文本帶句柄（讓 Worth 閘門可用）

- `recall_memories()` 回傳每行 `- [m:<id前8位>] <text>`（id＝Hindsight 記憶 id；與 `memory_worth` 的 id 同一來源）。
- `dshmid._filtered_mem()` 去掉句柄後再比較文字去重（句柄不參與 key），輸出保留句柄、仍上限 4 條。
- `memory_worth.record_retrieval()` 用 id 把 `retrieval` 與 `score(id)` 對上，Worth 閘門不再只做「相關性」一半。
- 三元素測試：`tests/test_memory_retrieval_handles.py`（6 checks：句柄格式、只留 8 位、無 id 不加句柄、墓碑過濾、同文字不同句柄去重、上限 4 條）。

## 3. 自檢：Verify-first／證據表

- `agents/self_observe.py`：`_REPAIR_PROMPT` 加「先列證據表，再決定 accept/fix_text/retry_step/replan/escalate；沒有證據就說證據不足」。
- `agents/honesty.py`：
  - 新增記憶聲明處理：`_MEMORY_CLAIM_RE`（「我記住了/記下來了」）＋`_only_memory_claims()`；`enforce(..., memory_evidence="")` 有記憶寫入證據才放行。
  - `_CLAIM` 召回補「已經查過/問過/看過/讀過」，EIR 由 0.2 → 0.000。
  - `agents/executor.py` 呼叫 `honesty.enforce()` 時傳入 `memory.memory_evidence(session_id)`。
- 小評測集：`tests/test_evidence_eval.py`（12 案例；rule 層 EIR=0.000、ECR=1.000），文件 `docs/評測-EIR-ECR-20261027.md`。
