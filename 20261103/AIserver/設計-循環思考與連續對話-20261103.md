# 設計：循環思考與連續對話（2026-11-03 晚，草案）

> 來源：主人 m12331 的追問與指正。先想清楚，再動手。
> 背景：目前是「一進一出」的回合制；她不知道自己有第二、第三次機會，於是急於在這一輪把話說完或草草收尾，對話沒有進展，也不會延續。

## 0. 主人原話要點（2026-11-03 21:26）

- 「会个 嗯 有什么问题？你是不是忘了她会有循环思考 和自我反思？这句话之后肯定会追加话的啊。」
- 「像你和人说话，你最先做的不是表达，而是说自己听到 或者 感受到，然后再说自己的结论和观点，总好过一句话讲完，这和 一进一出 没什么区别（回合制化）。」
- 「你好好想想循环思考到底如何实现先。循环思考是对于连续对话必要的条件。如果没有连续思考，这只会催生每次对话就和一个刚知道自己上下文的 AI 对话，而不是和一个知道刚才的话题、语境、氛围的连续对话性。」
- 「她不知道自己有第二次、第三次机会，导致急于求成，无法连续对话，只有一个对话赶紧结束，或者重复，根本没有连续对话，就是对话没有进展。」

## 1. 問題診斷

| 症狀 | 根因 |
|---|---|
| 一句話講完、急著收尾 | 架構上每輪只發一次回覆，她把「這一輪」當成「這次對話」的全部 |
| 像客服、不像人 | 她沒有「先接住再表達」的順序；也沒有「我的反應」可以放 |
| 下一輪像重新開機 | 沒有跨輪的對話思考狀態；每輪從歷史文字重建語境，沒有自己的立場與未完成的事 |
| 陪伴宣稱、附和 | 因為「這輪必須給出完整回答」，只能靠姿態補足 |
| 思考是 shadow | `mind_loop` 每 180 秒寫想法到 `thoughts.jsonl`，但沒有注入對話；她有想法，聊天時用不到 |

## 2. 設計原則（主人給的）

1. 先接住，再說觀點：先說「我聽到什麼／我感覺到什麼」，再說自己的結論。
2. 不必一輪講完：留白、留一句問話、留到下一輪。
3. 有第二次機會：她要知道對話還在，可以追加、可以回頭補。
4. 思考要跨輪：她的想法、疑惑、未说完的話，下一輪還在。
5. 用引導不用禁令：契約寫「你可以怎麼做」，不是「不准怎樣」。

## 3. 架構 v1（最小可用，先做這個）

### 3.1 對話思考線（per session）
- 檔案：`runtime/dialogue/<session_id>.json`（session_id 用 X-Session-Id；沒有就用日期）。
- 欄位：
  - `topic`：當前話題（例：主人說自己沒用）
  - `reading`：她對主人此刻的判讀（情緒、需求：要答案還是要陪）
  - `my_last_reply`：我剛才說了什麼
  - `open_loops`：還沒接完的（未答的問題、想問的話、想補的一句）
  - `next_move`：下一輪打算怎麼接（`listen`／`ask`／`answer`／`say_more`）
  - `affect`：T6 當下狀態快照（labels、mood、energy）
  - `updated_at`、`turn`
- 生命週期：對話閒置 6 小時後歸檔到 `runtime/dialogue/archive/`；不進 master 記憶（避免污染）。

### 3.2 回合後反思（post-turn reflection）
- 時機：她回覆已送出之後（不阻塞聊天延遲），背景執行。
- 輸入：主人在這一輪說的原話、她剛才的回覆、上一輪的思考線、T6 狀態。
- 輸出 JSON：`{topic, reading, open_loops[], next_move, say_more: bool, say_more_text: str}`
- 模型：qwen14b-16k，max_tokens 240，timeout 30s；失敗不影響主線，記 log。
- 寫入：更新思考線＋trace `07_dialogue_reflect`。

### 3.3 下一輪注入（continuity injection）
- 在 user message 的動態區加（≤300 字）：
  ```
  【我正在想】話題：…；我剛才的感覺：…；還沒接完：…
  【接下來】你可以先接著剛才的話說，不用重新開場；想問就問，不必急著收尾。
  ```
- 只在同一 session 連續對話（距上輪 < 30 分鐘）時注入；冷啟動不注入。

### 3.4 追加話（say_more，v2 再開）
- 若反思 `say_more` 為真，且本輪對話還活躍：等她主回覆後 6–15 秒，補發一句 ≤40 字。
- 上限：每個主人回合最多 1 句；主人已在輸入新訊息則取消。
- 通道：dshmid SSE 追加 delta；Discord 另發一條訊息。
- v1 先只記錄 `say_more_text` 到思考線，下一輪自然說出來（不改通道，風險最低）。

### 3.5 空檔延續（idle，接既有 mind_loop）
- mind_loop 已有每 180 秒 tick；v1 把「最近一輪對話的 open_loops」餵給它，讓它在主人沉默時想「我還沒問的那句」。
- 仍 `dry_run=true`，不主動發訊息；想法寫入 thoughts 與思考線；下一輪可被注入。

## 4. 契約與人格的引導句（不是禁令）

契約【對話】段（草案，待 prompt_audit 校驗）：
- 「你不需要在這一輪把話說完。先說你聽到什麼、你怎麼感覺，再說你的想法。」
- 「你想問就問；問了不必自己回答，留給主人。」
- 「如果還有話沒說完，下一輪接著說，不用重新開場。」
- 「主人沉默，不代表對話結束。」

人格層 v14 已寫「不擅長說話、一句講完」；v14 之後要補的是「先接住再說」，放契約（第二人稱）而不是人格（第一人稱），避免人格層承擔流程。

## 7. 風險

- 延遲：反思是非阻塞背景；聊天主線不變慢。
- 重複／吵：追加話上限 1 句＋主人輸入即取消；idle 不發。
- 幻覺：思考線只用於她自己的連貫性，不當事實對主人宣稱；事實仍走工具與記憶。
- 隱私：思考線只在本機 runtime，不入 git。
- 污染：思考線不寫 master；對話結束只留 session 摘要（既有 grounding 規則）。
