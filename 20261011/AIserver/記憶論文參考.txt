记忆演化框架：从 Storage 到 Experience
这篇综述已被 ACL 2026 Findings 接收。它提出了一个三阶段演化框架，把 LLM Agent 记忆机制的发展形式化为存储 → 反思 → 经验三个阶段，对应三种功能签名：轨迹保留 → 轨迹精化 → 跨轨迹抽象。

1. 核心问题：为什么需要这个框架
论文指出当前记忆研究存在两个障碍：

范式碎片化：研究在操作系统工程和认知科学之间摇摆，缺乏统一视角。

缺乏技术综合：大量方法只解决孤立阶段的问题，没有形成连贯的演化路线图。

你的 Hindsight-CN 本质上是一个存储 + 反思系统——它做 retain（存储）和 consolidate（反思），但还没有进入 Experience 阶段。

2. 三阶段深度拆解
阶段一：Storage（存储）
目标：忠实保留交互轨迹，解决 LLM 上下文窗口有限与交互历史无限增长之间的矛盾。

论文区分了三种存储模式：

线性 (Linear)	FIFO 队列，按时间排列	简单直接	容量有限
向量 (Vector)	编码到高维空间	容量大，支持语义检索	检索精度依赖 embedding
结构化 (Structured)	表、层级、图	容量大 + 可解释关系	索引延迟高


阶段二：Reflection（反思）
目标：解决存储的质量问题——原始轨迹不可避免地包含幻觉、逻辑错误和无效尝试。

论文区分了三种反思机制：

机制	                 反馈来源	      适用场景
内省 (Introspection)	模型内部知识	纠错、压缩长轨迹
环境 (Environment)  	外部环境信号	校准世界模型、优化策略
协调 (Coordination) 	多 Agent 共识	克服个体认知瓶颈
对你的映射：Hindsight 的 consolidate 属于内省反思——它用 LLM 自己判断哪些事实冲突、哪些该合并。你的元规则 M5（冲突不硬选）对应环境反思的思想——不强行选一个版本，而是保留多版本等待更多证据。

关键洞察：论文指出，反思后的记忆仍然是碎片化的，高度依赖上下文，检索成本高，且容易因上下文微小变化而诱发错误。
这正是你当前架构的瓶颈——Hindsight 的 fact 检索回来是一堆碎片，Q3 需要花大量 token 把它们拼成连贯回答。




阶段三：Experience（经验）
目标：从类似轨迹中提取通用启发式智慧，把轨迹从具体上下文中剥离，压缩记忆库，实现对未知环境的泛化。
论文将 Experience 分为显式 (Explicit) 和隐式 (Implicit) 两类：
显式经验：自然语言策略、可执行实体、可演化技能库
隐式经验：内化到模型参数中
对你的映射：你的 skills 库就是显式经验的雏形——把重复出现的任务（如点外卖）抽象成可复用的 skill。
但你目前缺少的是从轨迹中自动归纳出 skill 的能力。Hindsight 的 mental models 可以看作经验层的早期形式，但还没有系统化。




3. 前沿机制：Experience 阶段的两大变革
论文重点探索了 Experience 阶段的两个变革性机制：

主动探索 (Active Exploration / Proactive Exploration)
Agent 从被动记录者转变为目标驱动的经验收集者。

对你的启示：你的 Agent 目前是被动的——用户问什么，它查什么。主动探索意味着：当 Agent 发现某类任务反复出现且当前 skill 覆盖不足时，主动触发一次学习流程（搜索 + summarize + 存入技能库）。

跨轨迹抽象 (Cross-Trajectory Abstraction)
把孤立轨迹压缩成稳定的策略先验 (policy priors)，论文列举了四种操作逻辑：

对比归纳：成功 vs 失败轨迹对比

多粒度分块：不同粒度的经验切分

代码函数封装：把经验封装成可调用函数

微调内化：把经验写进模型参数

对你的启示：对比归纳是你最应该优先实现的——当 Hindsight 里同时存有成功和失败的交互轨迹时，让 LLM 对比它们，提取出“什么情况下应该做什么、什么情况下不应该做什么”的规则，写入 skills 库。

4. 论文指出的未来方向
综述最后给出四个未来方向：

动态触发模式：记忆机制应根据任务类型动态触发，而非固定流程——这直接支持你的 T1 分流设计。

工作记忆建设：工作记忆是记忆机制的核心——你当前缺少显式的工作记忆层（当前对话的临时状态）。

更全面的数据集：尤其是 Experience 阶段——你的评估集应该覆盖 skill 归纳场景。

分布式共享记忆 + 多模态记忆融合：长期方向。




目前記憶三大問題

启示一：你的拆解器需要用六维框架来评估和迭代
不要凭感觉调 prompt。为拆解器建一个小评估集（20-50 条），每条标注：应该拆成几个子任务、每个子任务的 mode 是什么。然后按六维框架测：

完整性：漏拆率
可执行性：skill 命中率
效率：平均拆解 token 数
泛化性：跨任务类型的准确率
启示二：你的记忆层目前卡在 Reflection 阶段，需要向 Experience 推进
Hindsight-CN 做的是 Storage + Reflection。你需要加一层 Experience Extractor：

text
Hindsight 轨迹
  ↓
[异步 Experience Extractor]
  ├─ 对比成功/失败轨迹
  ├─ 提取通用规则
  ├─ 写入 skills 库
  └─ 更新元规则候选（人工确认后生效）
启示三：你的工作记忆层是缺失的
论文明确指出“构建工作记忆是记忆机制的核心”。你当前的架构中，子任务状态表是临时变量，没有持久化。应该有一个显式的工作记忆层：

json
{
  "current_session": {
    "topic": "...",
    "active_subtasks": [...],
    "evidence_buffer": [...],
    "emotion_state": {...},
    "style_hint": "..."
  }
}
它在会话期间持续更新，会话结束后由 Experience Extractor 决定哪些内容值得写入长期记忆。
