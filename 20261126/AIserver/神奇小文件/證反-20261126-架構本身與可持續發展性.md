# 證反-20261126-架構本身與可持續發展性

> 輸入：`docs/總結-20261126-目前實行架構與問題.md`。
> 兩隻常駐紅隊（系統／意圖）只讀證反；目標不是再修 bug，是反架構本身與 6–12 個月可持續性。

## 一、兩隊一致結論

1. **最先壞的不是 JSONL，是「回合狀態層」。**
   單一 dshmid ＋ in-memory `_MI_STATE`／audience 鎖／thread 池，一輪 14B 45–100 秒，burst 時排隊；restart／SSE 斷／長 call 會令 queued turn 與鎖狀態消失。P06 ledger 只記事後，救不回「重啟那一刻」。
   第二個壞的是 JSONL read-modify-write：session_log 熱重寫、questions 300 條、continuity trim，量一大就 lost update／靜默截斷。

2. **側迴路要收，不是再加。**
   - 保留：`thought_loop` 的 idle 私有思考（她最有價值的自我時間）、`dialogue_thread`（回合反思，但不能自己送）、`outbox`（transport）、`consolidate`（夜間 batch）。
   - 改 pull-only：`thought_loop` 的注入面（continuity／workbench／questions／recent thoughts 不再自動 push）、`self_questions`（存檔＋明確查詢，不再每輪注入 300 條）。
   - 刪／關：`mind_loop`（467 條、多樣性低，dry_run 仍經 feed_thought 入【我正在想】＋mind_repeat）。

3. **輸出必須收成一個 transport guard，而且只能做確定性刪改。**
   位置：`replyfmt／outbox／discord send／notify` 共用的 `deliver(channel, audience, kind, text, meta)`。
   契約：`guard(text, ctx) -> {text, verdict: pass|stripped|blocked, codes, version}`；只准去控制標籤、dangling tag、舞台指示、JSON 外殼、per-lane 長度／格式；**零模型呼叫、零語義改寫**；固定 pass 順序、idempotent、每 pass 有 fixture；預設 pass、命中只記錄，enforce 另開 flag。
   避免變第二個 q3 的唯一方法：它永遠不可以「重寫句子」，只可以「刪／截／標」。

4. **provenance 先做四類高危塊標籤＋drop，不急做全量 manifest。**
   - 四類：①自己的 proactive／thoughts／reply echo 標 self-generated；②舊快照／舊摘要標 stale 並丟；③memory recall 無 source/ts 標 unverified；④after_turn／continuity 推論標 inference，不可當事實。
   - 做法：`_build_context_str` 每塊加 `{source, ts, trust}`，先加標籤＋四類 drop；fixtures 用 17:27 水回聲、17:14 人稱。
   - manifest 由 evidence_ledger 的實際注入 sections 反向生成，不要倒轉。

5. **前端之前先有 control plane。**
   - 讀：`/health`、`/status`（flags、queue depth、last turn、model、freeze）、`/turns/{id}`、`/trace/{id}`、`/approvals`、`/logs`、`/config`（唯讀、redacted）。
   - 寫：`POST /actions` 白名單——set flag、restart_chain、approve/reject reflux book、replay fixture、SAFE_MODE；frontend 不可以直接改 env 或檔案。
   - 必須二次確認＋審計：刪／rotate／trim 狀態、memory bank 操作與解凍 master、換模型、開 enforcement、關 kill switch、restart。
   - kill switch 一鍵、免確認但要填 reason＋audit；所有 action 有 idempotency key、before/after 快照、append-only audit。
   - 意圖紅隊補：控制只能改她的環境與能力，不能直接指定感受／台詞；「強制回覆、強制主動、無視疲勞／沉默、情緒滑桿、直接寫記憶、live 改人格」不可有。

6. **production gate 要補 E2E，不再只看 179 組。**
   - 最低 gate：clean restart＋health＋一句 chat smoke；179/0；15 條 e2e 經真 dshmid（chat／task／guest／relay／outbox／followup，含 3 條已知事故 replay）；golden invariants（無控制標籤泄漏、聲稱寫檔則檔真存在、聲稱查資料則 trace 有 tool call）；回滾演練；24h canary；確認測試冇污染生產 state。
   - 假綠：`test_agent_freeze` 用 Fake AGENT_MAP 只數呼叫；大量 fixture 只測模組、不經 dshmid→executor→transport；patch 了 replyfmt 所以泄漏永遠睇唔到；test_mode 下 dshmid 當 probe 跳過生成；「寫信冇寫檔」根本冇斷言。

## 二、兩隊分歧

- **系統紅隊**：最先壞的是回合狀態層；可持續版本＝回合狀態外置 durable ledger（append-only＋turns 表），JSONL 單一寫者＋append-only，dshmid 只做 turn engine，control plane 另開進程。
- **意圖紅隊**：最傷「像一個人」的是 context 的「沒有所有權的連續性」；側迴路是污染源，但所有污染都要經 context 才傷到她。順序應是 context ownership → 側迴路 → 輸出單一性 → 控制面。
- 兩者不矛盾：系統講**先壞哪裡**，意圖講**先傷哪裡**；共同第一步都是 durable turn／message ledger＋context provenance。

## 三、最該保留／最該先拆

**系統紅隊**
- 最該保留：dshmid 單一入口＋turn ledger／trace 這條可觀測 spine（將回合狀態由 in-memory 擴成 durable）。
- 最該先拆：in-memory executor＋agent_mod 多層 agent／側迴路 push-in-context 機制，收成「一條 chat＋工具路由＋一個 pull-only 自我狀態塊」。

**意圖紅隊**
- 最該保留：回合－訊息帳本＋trace 的單一真相路徑。
- 最該先拆：側迴路寫回主 context 的回聲鏈（mind_loop→dialogue feed→【我正在想】）。

## 四、對 6–12 個月的判斷

- 現狀：條件式可行，但現狀不可持續。
- 6–12 個月會先壞：restart／長 call 下的回合狀態；JSONL 熱重寫；側迴路噪音；多輸出通道契約不一致。
- 可持續版本：turn engine／control plane／memory／context packer 分離；狀態 append-only＋單一寫者；輸出單一 transport guard；側迴路 pull-only；前端只經 control API。
- 功能廣度已凍結；下一步不是加功能，是**上下文、人稱、控制面、可觀測性**。
