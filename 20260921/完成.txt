一、手机访问 DSH 报 403 的修复
问题起点
手机通过 Tailscale 访问 https://aiserver.tail2fe40b.ts.net/ 时，DSH 报 403，提示 listProviders failed。

根本原因
DSH 只信任 Host 头为 127.0.0.1:3080 或 localhost:3080 的请求，Tailscale 域名不在白名单里。这是 DSH 的安全设计，防止远程请求绕过本机限制。

尝试过但失败的方案：Caddy 反向代理
安装 Caddy，监听 127.0.0.1:3081，转发到 127.0.0.1:3080

用 header_up 改写 Host、Origin、Referer

Tailscale Serve 指向 127.0.0.1:3081

失败原因：DSH 生成的 HTML 里 JS 资源路径是绝对地址 http://127.0.0.1:3080/static/...，页面是 HTTPS，浏览器拦截混合内容，主 JS 没加载，手机白屏

结论：标准 Caddy 无法改写响应体，放弃

最终成功的方案：DSH 原生 --trusted-host
修改 DSH 的 systemd 服务，加 --trusted-host aiserver.tail2fe40b.ts.net

Tailscale Serve 直接指向 127.0.0.1:3080，去掉 Caddy

停用 Caddy

过程中踩的坑
端口冲突：手动跑的 ssh -L 3080:127.0.0.1:3080 占用 3080，DSH 启动时 EADDRINUSE 反复重启。杀掉进程后解决。

插件冲突：dsh-settings-remote 依赖不存在的 apiProxy 服务，激活失败导致 DSH 崩溃。卸载后解决。

模型 404：DSH 的 settings.yaml 里 baseURL 仍是 11434（直连 Ollama），而模型名 dshmid 只存在于中间层。DSH 把 dshmid 发给 Ollama，Ollama 不认识。

当前状态
DSH 正常运行，监听 127.0.0.1:3080

Tailscale Serve 直连 3080，https://aiserver.tail2fe40b.ts.net/ 可访问

三、接 ASTRA 做工具规划（不执行）
架构简化
取消原来的"Qwen 处理 REMINDER / RECORD"分支，改成：

text
DSH → 中间层
    → DSR1 判断意图
        ├── CHAT → Qwen 回复
        └── 其他（QUERY / TASK / REMINDER / RECORD）→ ASTRA 规划工具 → 显示待处理

五、发现的问题
1. ASTRA 推理耗时较长
你好 只需 9.5s（Qwen 直出）

提醒 用了 20.4s（ASTRA 加载 + 规划）

创建文件 用了 62.8s（ASTRA 加载 + 规划 + 思考）

原因：显存只有 16GB，DSR1（9GB）和 ASTRA（9.4GB）不能同时常驻，每次切换都要重新加载模型。

优化方向（后续）：

调整 OLLAMA_KEEP_ALIVE 时间

考虑让 DSR1 常驻，ASTRA 按需加载

或评估是否把 DSR1 也换成更小的模型

2. ASTRA 思考过程被记录下来
astra_plan 的日志里能看到 ASTRA 的完整思考内容（"用户想要设置一个提醒..."），这些应该只用于调试，不应该作为最终输出的一部分。
