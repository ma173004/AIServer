三、实施步骤
安装 Node.js 22

通过 NodeSource 脚本安装 nodejs 和 npm。

修复 npm 全局安装权限

将 npm 全局目录改为用户级：npm config set prefix '~/.npm-global'，并加入 PATH。

解决 EACCES 权限报错，成功全局安装 @deepseek-ai/dsh。

安装 Ollama 并配置数据路径

安装 Ollama，使用 systemd override 设置 OLLAMA_MODELS=/data/ai/ollama-models 和 OLLAMA_HOST=0.0.0.0。

拉取 deepseek-r1:14b（9.0 GB），确认模型运行流畅。

部署 DSH

全局安装 DSH，设置 DSH_HOME=/data/ai/dsh-home。

发现 DSH 出于安全考虑，拒绝监听 0.0.0.0，只允许 127.0.0.1。

配置 DSH 与 Ollama 对接

在 DSH Web UI 的“模型”设置中，手动添加自定义提供方（Provider）。

API 地址：http://127.0.0.1:11434/v1，协议：openai-completions。

在“模型目录”中显式填入 deepseek-r1:14b，解决“provider resolves no models”报错。

远程访问方案（SSH 隧道）

放弃 0.0.0.0 和 Tailscale Serve 的复杂插件方案。

采用 SSH 本地端口转发：ssh -f -N -L 3080:127.0.0.1:3080 msixj@10.0.0.2。

利用 Windows 计划任务 + PowerShell 脚本（dsh-tunnel.ps1）实现开机自启和后台持久运行。

服务自启与恢复

给 FileBrowser 容器设置 --restart=always。

检查重启后的 Ollama、DSH、Samba、Tailscale、10G 网卡均正常恢复运行。

四、关键报错与解决方案
ERR_PNPM_GIT_DEP_PREPARE_NOT_ALLOWED：pnpm 拦截 git 托管依赖的构建脚本。已在 pnpm-workspace.yaml 的 allowBuilds 中添加完整带 hash 的键值。

dsh: pnpm not found on PATH：DSH 插件管理依赖 pnpm，执行 npm install -g pnpm 解决。

llm-deepseek: no API key for provider route "deepseek-official"：DSH 默认模型指向 DeepSeek 官方。在 Web UI 中正确配置 Ollama 为提供方，并填入本地模型名解决。

provider 'ollama' resolves no models：DSH 需要显式声明模型列表，在 Web UI 的模型目录中手动添加 deepseek-r1:14b。

401 Unauthorized / 403 Forbidden（DSH 远程访问）：DSH 只信任 127.0.0.1 本机请求。通过 SSH 隧道将远程请求伪装成本机回环请求，绕过安全限制。

docker: filebrowser Exited（重启后容器未启动）：缺少 --restart=always 参数，已补上。
