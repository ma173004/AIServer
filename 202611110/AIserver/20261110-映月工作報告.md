## 2. 今晚發生的問題（逐條：現象→根因→修法→狀態）

### 2.1 她「重複自己的話」、同一時間兩條訊息
- **現象**：23:15 回覆「我在歸類與標記重點…紙張撕扯聲…」，1 秒後又送一條「紙張撕扯聲好像還在耳邊…」，內容幾乎是回覆最後一句；23:00 也有連續兩條。
- **根因**：不是重複生成，是兩個出口。reply 走管線；`after_turn` 的思考 `say` 經 `outbox.emit` → 通知中心（kind=scene_message）→ bot DM，晚 1–10 秒送到。`followup` 也會補一句（延遲 12 秒）。
- **修法**：`thought_loop` 發 say 前檢查 180 秒內最近回覆，若是回聲（去標點包含或 difflib≥0.55）就不發；`discord_bot` 記錄 `last_reply.json`，followup 與回覆相似度≥0.5 跳過；followup 延遲 12→25 秒。
- **狀態**：已上線（`749e86d`），等真實對話驗證。

### 2.2 同一輪可能出現多條可見訊息（MIMO 割裂感）
- **根因**：一輪輸入有多個出口：reply、after_turn 主動訊息、followup、提醒、idle 主動訊息。
- **修法（今晚先做輸出端）**：after_turn 回聲抑制＋followup 守門＝一輪最多一條。
- **下一步**：真正 MIMO 設計——輸出端全部改成「排到下一輪的【我剛才想跟你說的】或靜默 N 分鐘才發」；輸入端把生成中收到的訊息合併到下一輪（合併視窗 700ms→1.5–2s），或取消當前回覆合併重跑。

### 2.3 自我反思人稱錯亂（她/他指主人）
- **現象**：`07_dialogue_reflect` 輸出「我問問她是否需要休息」「我會輕聲問她是否需要暫停整理」。
- **根因**：反思 prompt 只對 `reading` 欄要求「我」開頭禁「她/映月」，其他欄位沒有規則、輸出也沒有正規化；**原測試只驗欄位存在，沒驗人稱**（這是我的檢查缺口）。
- **修法**：`dialogue_thread._normalize_person()`（她/他→主人）＋ `_REFLECT_SYSTEM` 明寫人稱；6 欄位解析時全部過 normalize；測試 +4 條人稱檢查。
- **狀態**：已上線。

### 2.4 工作臺她看不到（「我沒有個人的工作臺」）

- **修法**：`chat_agent._workbench_context_section()` 把工作臺摘要（620 字）固定放進 context；預算超標先砍它，不砍對話。

### 2.5 DM 落盤整晚靜默失敗（新發現的真 bug）
- **現象**：她不知道自己在 DM 裡說過什麼。

- **修法**：補簽名；重啟 bot；現在 DM（含附件 metadata）正常落盤。
- **教訓**：寫檔失敗被 try/except 吞掉且只記 log，等於無聲丟資料。之後關鍵落盤要計數/告警。

## 4. 教訓

1. **提示詞規矩要當成硬檢查**：白熊、人稱、預算——今晚三樣都靠主人指出。以後改完 prompt 必跑 `prompt_audit.py`＋人稱掃描＋否定詞計數。
2. **測試要測行為，不只要測結構**：反思欄位存在≠人稱正確；回覆有內容≠不是回聲。結構測試給假安全感。
3. **靜默失敗最貴**：`_record_dm` 吞錯一整晚，她因此「不知道自己說過什麼」。關鍵落盤要有計數/告警。
4. **同一個東西兩個出口就會重複**：reply 與 after_turn 都能發訊息 → 主人看到兩條。輸出端要有單一出口/守門。
5. **16GB VRAM 只能常駐一個大模型**：任何「同時載兩個」的設計都會互踢；VLM 必須看完即釋放。
6. **陳年遺產會在模型變強時爆出來**：persona.txt 一直存在，q3 服從性一強就顯形。升級模型前先掃古舊 prompt/config。
